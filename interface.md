# Deployment Interfaces

This inventory describes the interfaces available after a successful deployment. Replace the example hostnames with the values configured in `.env`.

| Interface, dashboard, or service | `NGINX_ENABLED=false` | `NGINX_ENABLED=true` |
| --- | --- | --- |
| LiteLLM OpenAI-compatible API | URI: `http://<SERVER-IP>:4000/v1`<br>Port: `4000`<br>Available to developers and applications | URI: `https://<API_HOSTNAME>/v1`<br>Public port: `443` -> internal `4000`<br>Available to developers and applications |
| LiteLLM dashboard | URI: `http://<SERVER-IP>:4000/ui`<br>Port: `4000`<br>Admin access to models, keys, budgets, and proxy settings | URI: `https://<API_HOSTNAME>/ui`<br>Public port: `443` -> internal `4000`<br>Admin access to models, keys, budgets, and proxy settings |
| LiteLLM readiness | URI: `http://<SERVER-IP>:4000/health/readiness`<br>Port: `4000`<br>Admin and monitoring health check | URI: `https://<API_HOSTNAME>/health/readiness`<br>Public port: `443` -> internal `4000`<br>Admin and monitoring health check |
| Langfuse dashboard | Not externally available.<br>Internal URI: `http://langfuse:3000`<br>Internal port: `3000` | URI: `https://<OBSERVABILITY_HOSTNAME>`<br>Public port: `443` -> internal `3000`<br>Admins and developers can view traces, inputs, outputs, costs, and agent workflows |
| Langfuse health/API | Internal URI: `http://langfuse:3000/api/public/health` and `/api/*`<br>Internal port: `3000`<br>Available to the Compose network | URI: `https://<OBSERVABILITY_HOSTNAME>/api/public/health` and `/api/*`<br>Public port: `443` -> internal `3000`<br>Authenticated monitoring and integrations |
| vLLM model API | Internal URI: `http://vllm-<id>:<port>/v1`<br>Configured internal port<br>Available to LiteLLM only | Internal URI: `http://vllm-<id>:<port>/v1`<br>Configured internal port<br>Available to LiteLLM only |
| vLLM health probe | Internal URI: `http://vllm-<id>:<port>/health`<br>Configured internal port<br>Used by monitoring | Internal URI: `http://vllm-<id>:<port>/health`<br>Configured internal port<br>Used by monitoring and Nginx-backed operations |
| Nginx reverse proxy | Disabled; no proxy or TLS endpoint | URI: `https://<API_HOSTNAME>` and `https://<OBSERVABILITY_HOSTNAME>`<br>Ports: `80` for redirect and `443` for TLS<br>Secure public boundary for LiteLLM and Langfuse |
| dstack model service | URI and port are assigned by the external dstack gateway<br>Available according to dstack configuration | URI and port are assigned by the external dstack gateway<br>Available according to dstack configuration |
| dstack dashboard/control plane | External organization-provided URI and port<br>Admin access to scheduling, provisioning, logs, and operations | External organization-provided URI and port<br>Admin access to scheduling, provisioning, logs, and operations |

## Internal-only infrastructure:

These services are not host-published in either Nginx mode:

| Service | Internal URI and port | Purpose |
| --- | --- | --- |
| PostgreSQL | `db:5432` | LiteLLM and Langfuse metadata and application storage |
| ClickHouse | `http://langfuse-clickhouse:8123` and native port `9000` | Langfuse trace and event analytics storage |
| Redis | `redis://langfuse-redis:6379` | Langfuse queue and cache coordination |
| MinIO S3 | `http://langfuse-minio:9000` | Langfuse event and object storage |
| MinIO console | Internal port `9001` | Storage administration; not externally published |

## Important prerequisites:

- Replace `api.example.internal` and `observability.example.internal` with internal DNS names in `API_HOSTNAME` and `OBSERVABILITY_HOSTNAME`.
- When `NGINX_ENABLED=true`, provide the internal-CA certificate and key configured by `NGINX_TLS_CERTIFICATE` and `NGINX_TLS_CERTIFICATE_KEY`.
- Create LiteLLM virtual keys for developers. Do not distribute `LITELLM_MASTER_KEY`.
- Configure Langfuse users, project keys, and RBAC for admin and developer access.
- Mirror or preload every pinned container image in the air-gapped registry before deployment.
- Ensure the configured host firewall allows only the intended public ports: `4000` when Nginx is disabled, or `80/443` when Nginx is enabled.
- Configure the dstack gateway and dashboard separately; they are not generated by this repository.

## **Access by audience**

- **Administrators:** Use the LiteLLM dashboard. When Nginx is enabled, use `https://<API_HOSTNAME>/ui`; otherwise use `http://<SERVER-IP>:4000/ui`. Administrators may also use Langfuse at the observability URI when enabled and the external dstack dashboard.
- **Developers:** Use the LiteLLM API with a virtual key. The endpoint is `https://<API_HOSTNAME>/v1` with Nginx enabled, or `http://<SERVER-IP>:4000/v1` with Nginx disabled. Developers may use Langfuse according to its RBAC policy.
- **Users and applications:** Consume the LiteLLM API through an application-specific virtual key. They do not receive admin credentials, Langfuse secrets, database credentials, or direct vLLM access.
- **Monitoring systems:** Check LiteLLM readiness, Langfuse health when exposed, and vLLM `/health` probes according to the selected network mode.

## Disabling Nginx also means:

- LiteLLM is exposed directly over HTTP on host port `4000`.
- There is no HTTPS termination, TLS redirect, or reverse-proxy access control.
- The LiteLLM dashboard and API use the direct `http://<SERVER-IP>:4000` address.
- Langfuse remains an internal service on port `3000`; its dashboard is not externally available.
- vLLM, PostgreSQL, ClickHouse, Redis, and MinIO remain internal-only.
- `nginx.conf`, Nginx TLS mounts, and the Nginx service are omitted from the generated deployment.
- Any old `nginx.conf` file left on disk is unused and can be removed manually.
- Use a firewall or an external secured gateway if port `4000` must be reachable beyond the trusted internal network.
